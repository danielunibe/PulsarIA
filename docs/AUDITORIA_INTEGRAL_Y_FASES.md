## Resumen ejecutivo

- **El usuario ya puede descargar gratis `v0.1.0-eval.3` desde GitHub.** Esa versión publicada es anterior al candidato Beta 2.
- **Beta 2 aún no es una descarga pública:** está en el PR borrador [#2](https://github.com/danielunibe/PulsarIA/pull/2). El workflow de bootstrap y la corrección del manifiesto pasaron CI en el run [36381502093](https://github.com/danielunibe/PulsarIA/actions/runs/36381502093); el head actual `e63233f0` pasó estructura, frontend, Rust y Python en el run [36382419653](https://github.com/danielunibe/PulsarIA/actions/runs/36382419653). El YAML y digest pasan validación local, pero la extracción real desde el instalador semilla aún no se ha ejecutado en Actions.
- **La principal prioridad funcional es terminar aceptación nativa.** En el preview web no hay acceso a la biblioteca local; la alerta y el reintento se muestran, pero eso no demuestra el comportamiento de SQLite/Tauri.
- **Se corrigieron localmente cuatro defectos de comunicación/usabilidad:** error de búsqueda junto con “sin resultados”, enlaces inválidos escondidos dentro del CTA, nombre accesible insuficiente del campo de perfil y recorte a una sola línea de la alerta de biblioteca.
- El fallo de red esperado del preview queda como advertencia de consola, así no abre el overlay rojo de Next Dev; los demás errores siguen como errores.
- **La salida Beta 2 sigue bloqueada** por revisión humana de licencia/notices y datos confirmados del titular. El Environment `direct-download` ya exige aprobación humana, limita despliegues a `main`, desactiva el bypass administrativo y conserva `DIRECT_DOWNLOAD_RELEASE_READY=false`. El runtime directo parte del instalador público `eval.3` con SHA-256 fijado; la comparación de manifiestos encontró 38/38 registros runtime no-worker iguales, pero el bootstrap aún no se ejecuta en Actions. La aceptación nativa de fases 2–7 y el smoke TikTok autorizado siguen como validaciones del producto; firma Authenticode y updater corresponden al flujo estable.
- El workflow firmado actual exige certificado Authenticode, claves/firmas Tauri updater, runtime externo y `RELEASE_READY` también para prereleases. La ruta manual NSIS directa ya está en el PR y no requiere Authenticode ni updater; aún no se ejecuta y requiere terminar los gates legales y la aprobación de publicación.

## Recomendación legal práctica para el titular

La respuesta segura hoy es **“aún no lo sé”**. No completar `legal/release-manifest.json` con el nombre del autor de GitHub ni con un domicilio inferido. Para preparar una respuesta válida sin exponer datos de más:

1. **Titular:** identificar primero quién posee realmente el código, marca, textos y assets. Puede ser una persona física o una entidad, pero hay que revisar contribuciones, empleo/contratos y licencias antes de escribir un nombre legal.
2. **Correo:** crear una cuenta dedicada y controlada por el titular, por ejemplo `legal@<dominio-de-Pulsaria>` o `privacy@<dominio-de-Pulsaria>`, con autenticación multifactor y una persona responsable de revisarla. No usar un correo privado como dato público por defecto.
3. **Domicilio:** consultar con asesoría mexicana qué domicilio real y autorizado puede recibir notificaciones. Primero evaluar oficina comercial propia; si no existe, preguntar a un abogado o representante si acepta formalmente ese encargo y si la dirección sirve para este aviso. No asumir que un apartado postal o una oficina virtual basta, y no publicar la vivienda particular por defecto.
4. **Aprobación:** no marcar `legal_approval` como aprobado hasta que el titular, tras leer las versiones exactas, confirme la revisión de licencia, EULA, privacidad, términos, copyright/takedown y notices. No puedo otorgar ese consentimiento en su nombre.
5. **Smoke live:** dejarlo pendiente; se necesita una URL TikTok autorizada. No hace falta para la descarga pública ya existente.

El artículo 15(I) de la LFPDPPP vigente exige que el aviso de privacidad incluya la identidad y el domicilio de quien resulte responsable del tratamiento. La ley no resuelve por sí sola quién ocupa ese papel ni qué domicilio concreto corresponde a Pulsaria; eso debe confirmarse con asesoría mexicana antes de publicar. El texto consultado de la Cámara de Diputados indica última reforma DOF 14-11-2025. [Ley vigente, Cámara de Diputados](https://www.diputados.gob.mx/LeyesBiblio/pdf/LFPDPPP.pdf).

La publicación también requiere cotejar dependencias, modelos y notices del artefacto exacto: FFmpeg explica sus condiciones de redistribución y que compilar con partes GPL habilitadas cambia el régimen aplicable. Esto identifica una revisión pendiente, no una conclusión legal sobre Pulsaria. [FFmpeg: licencia y consideraciones legales](https://ffmpeg.org/legal.html).

## Cómo continuar fase por fase

La fase activa es **2: mejorar Inicio y estados de biblioteca**; el cambio está implementado y su CI pasó, pero requiere aceptación nativa. Después sigue la fase 3. Cada cierre debe anotar evidencia y límites: navegador ≠ Tauri; build ≠ smoke instalado; smoke offline ≠ TikTok live; CI ≠ aprobación legal ni aceptación visual humana.
